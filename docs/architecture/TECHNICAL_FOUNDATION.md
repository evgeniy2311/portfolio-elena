# Технический фундамент

Статус: рекомендация до выбора концепции.

## Рекомендуемый стек

- Next.js + TypeScript;
- Tailwind CSS или CSS Modules с дизайн-токенами;
- Motion для React для точечных переходов;
- локальные структурированные MDX/JSON-кейсы на первой версии;
- Vercel или аналогичный Node/edge-хостинг;
- оптимизация изображений через `next/image` и генерация AVIF/WebP;
- Plausible/Umami или другая минимальная аналитика после решения о consent.

## Почему не конструктор по умолчанию

Framer/Webflow быстрее для стандартного портфолио, но кастомный код лучше подходит для авторской механики листания кейсов, строгой производительности изображений и воспроизводимого процесса между AI-агентами. После выбора спокойной концепции B можно повторно оценить Framer как более простой вариант поддержки.

## Быстрое сравнение путей

| Путь | Скорость запуска | Уникальность | Работа с кейсами | Поддержка | Предварительный выбор |
|---|---:|---:|---:|---:|---|
| Framer | высокая | средняя/высокая | CMS, достаточно для v1 | проще | прототип A/B |
| Readymag | высокая | высокая | слабее для растущей базы | средняя | moodboard A/C |
| Webflow | средняя | средняя/высокая | сильная CMS | средняя | production B |
| Next.js | ниже | максимальная | любая модель | требует разработки | production A+B |

Финальное решение принимается после выбора визуальной концепции и оценки того, кто будет добавлять новые работы после запуска.

## Производительность

- hero содержит не более одного priority-изображения;
- остальные изображения загружаются лениво;
- размеры контейнеров резервируются до загрузки;
- thumbnail и полноразмерная версия создаются отдельно;
- анимации используют в основном transform/opacity;
- тяжёлая motion-логика не выполняется при reduced motion;
- целевой размер начальной загрузки устанавливается после прототипа.

## Адаптивность

- проектирование начинается с 375 px;
- touch target минимум 44×44 px;
- интеракции hover имеют эквивалент по tap/focus;
- текст основного содержания минимум 16 px на mobile;
- никаких горизонтальных переполнений страницы;
- горизонтальная галерея всегда имеет понятный счётчик и управление.

## Качество

Планируемые проверки после появления кода:

- TypeScript и lint;
- unit-тесты преобразования контента;
- Playwright для главного сценария и навигации кейсов;
- axe/accessibility audit;
- визуальные скриншоты на 375/768/1024/1440;
- Lighthouse для mobile и desktop;
- проверка `prefers-reduced-motion`.

## Решения, которые пока не приняты

- точный стек и хостинг;
- CMS или Git-based content;
- домен;
- аналитика;
- форма заявки или только Telegram;
- русский или RU/EN;
- выбранная motion-библиотека.
